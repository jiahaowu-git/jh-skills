# Edge Cases (v4.0)

## 1. 中文译名表 (Russian SKU → Chinese)

| Russian title contains | 中文译名 |
|---|---|
| стул / кресло / табурет | 椅子 / 扶手椅 / 凳子 |
| стол (generic) | 桌子 |
| стол-книжка / трансформер | 折叠变形桌 |
| швабра | 拖把 |
| швабра spray mop / water spraymop | 喷水拖把 |
| швабра с отжимом / с ведром | 脱水拖把 / 带桶拖把 |
| комплект для уборки | 清洁套装 |
| палатка / тент | 帐篷 |
| тележка (universal/hand truck) | 手推车（跨品类） |
| коврик (мат/foam/PVC) | 地垫 / 防滑垫 |
| белый / серый / чёрный / голубой | 白色 / 灰色 / 黑色 / 蓝色 |

Brand names (Aurora, Deerma, Mika, Zetter, IKEA, Yueliangyi, etc.) are kept as-is.

If unsure, give a literal translation — never invent brand positioning.

## 2. 样本量与置信度

| 总样本 (`COMMENT`) | 报告处理 |
|---|---|
| < 20 | ⚠️ 极小样本,置信度低,仅供形式参考 |
| 20-50 | ⚠️ 样本量较小,统计意义有限 |
| 50-100 | 正常,无需警告 |
| > 100 | 充足,作为主要依据 |

报告结构不因样本小而省略字段——按完整 9 项输出,样本小用 ⚠️ 标注。

## 3. 零差评商品 (`NEGATIVE = 0`)

零差评 ≠ 零问题。完整流程:

1. 确认 `groupSummary.NEGATIVE = 0`
2. 查 5★ 评论的 `minus` 字段(罕见但可能存在):5★ 但 `minus` 非空 → 视为"隐藏缺点",在字段 9 列出
3. 查 4★ 评论内容:4★ 通常是"有保留但仍推荐"模式
4. 若全无问题 → 字段 9 写 `没有差评`
5. 样本量 < 50 时必须标"⚠️ 样本量小,100% 好评置信度低"

## 4. 错挂评论 (wrong-product)

**信号**: 评论内容关键词与商品完全无关(例: 拖把商品出现"вешалка/смартфон/одежда")。

**处理**:
- 不静默删除 — 用户需要知道存在错挂评论,这是数据真实性的一部分
- 在字段 9 标 `(K) ⚠️ 数据异常:1 条评价实为 X(非本商品),已剔除`
- 数字对账包含该项: `总差评 = 主题合计 + 1(异常剔除)`

## 5. tiny-sample 译文 (len(neg) ≤ 10)

**保留**: 中文翻译 + 对应星级 — `(N) 中文翻译 (N星)`

**禁止保留**: 原文 quote / 作者 / 日期 / 一句话摘要

**禁止翻译动作**:
- 归纳压缩: 把多个具体故障压成"质量差"
- 改写语气: 把买家吐槽改成客观陈述
- 增删事实: 原文没说的不能补
- 扩写短评: "Нормально." 不能扩成"我觉得还行"

**允许翻译动作**:
- 句式重排以符合中文表达习惯
- 长俄语句子拆分
- 主谓宾顺序调换

**示例对照**:
| 原文 | 译文 | 评估 |
|---|---|---|
| "Через 5 минут сломалась ручка, через 10 понял, что она ничего не выжимает" | "五分钟手柄就断了,十分钟后发现它根本不脱水" | ✅ 标准 — 自然、逐句对应、保留时间点和两个独立故障 |
| 同上 | "这拖把不耐用" | ❌ 归纳压缩 — 丢了两个时间点和两个故障 |
| 同上 | "五分钟手柄就断了,脱水功能不太好" | ⚠️ 半压缩 — 软化"完全不脱水"丢了时间逻辑 |

## 6. 跨品类商品

skill 不限制品类(沙发、帐篷、拖把、手推车、地垫均接受),但:

- 不要与其他品类商品做横向对比表(单 URL = 单报告)
- 关键发现里如涉及"与其他类型对比"应明确"不可与 X 品类混用"

## 7. 评分矛盾 (1-3★ 但文本实际在夸商品)

**信号**: 文本含正向词(хорош/удобн/нравит/жақсы/керемет/good/great 等)但评分 ≤ 3。

**处理**: 这类评论由 `scripts/kaspi_review.py triage()` 自动识别并归入"其他",在 commentary 中说明"其他"大小受评分矛盾影响——这是信息,不是聚类 bug。

不要试图把它重新标记成"矛盾"主题——v3.1 catch-all 已经正确处理。
